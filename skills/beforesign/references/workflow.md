# Review workflow

1. Identify Ethereum (1), Base (8453), Arbitrum One (42161), Optimism (10), Polygon PoS (137), or Gnosis (100). Confirm the Safe address, network, and signing method.
2. For Safe links, parse identifiers, use the official Safe Transaction Service for that network, and retrieve the complete proposal. Do not follow arbitrary supplied URLs or trust displayed labels. Compare proposal hash to the computed hash. Report API authentication failures; request complete JSON as fallback.
3. Normalize Safe fields: to, value, data, operation, safeTxGas, baseGas, gasPrice, gasToken, refundReceiver, nonce, plus safe and chainId. Typed data uses message and domain. Missing signed fields must be requested, never defaulted, including nonce. Raw calldata can only receive partial decoding without context.
4. Run the helper. Local hashing targets standard Safe 1.3.x/1.4.x EIP-712 domains. An unverified version means the hash is provisional. An on-chain mismatch is a critical discrepancy. Do not claim verification after RPC failure.
5. Fetch verified ABI and source via Etherscan V2 with optional ETHERSCAN_API_KEY, or Sourcify. Report unavailable source explicitly. Resolve Safe singleton and EIP-1967 implementation/beacon storage against the recorded block; inspect implementation source. Do not equate verification with trust. Unresolved proxy patterns are coverage gaps.
6. Decode using verified ABI. Resolve standard Safe MultiSend batches in order, retaining each destination, value, operation, and payload. Bound investigation to 8 nesting levels, 100 calls, 30 requests, and 2 MB per response; disclose limits reached. Unknown selectors are unknown, not harmless. Never present ABI selector guesses as verified.
7. Investigate native/token/NFT transfers, allowances and operators, arbitrary delegatecalls, owner and threshold changes, modules, guards, fallback handlers, upgrades, refund parameters, recipients, and relevant chain state. Compare against intended actions. Delegatecall executes in the Safe storage context. Check actual addresses rather than names. No simulation is performed; describe effects as authorized or inferred rather than observed execution.
8. Explain findings with source addresses, functions, URLs, block provenance, and uncertainties. Separate helper checks from agent interpretation. Return local Safe transaction hash and on-chain comparison, never confuse these with an executed transaction hash. The helper emits the full Safe hash, domain separator and struct hash separately. Match the exact device label and signing method; do not prescribe which value a device displays without checking that context. Ask signing method/device before prescribing a comparison.

If source retrieval, nested decoding, proxy resolution, or signing verification cannot be completed, explicitly mark that review incomplete. The helper retrieves proposals and verified source, resolves standard proxies, decodes nested batches and common calls, and gathers Safe/token state. The agent must inspect the returned source for arbitrary or dynamic behavior, validate recipient intent, and explain concrete effects. Helper findings are not an exhaustive audit.
